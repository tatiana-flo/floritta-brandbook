Что это

  • Новая оболочка CRM на утверждённом брендбуке: Ivory, квадрат, Cormorant Infant + Jost. Всё в JS на демо-данных: 40 заказов, 12 сотрудников, 25 клиентов, 30 товаров.
  • Слева – тема, плотность, роль, размер. ⌘K – палитра: заказ по номеру, клиент по телефону, команды. Клавиши: N новый заказ, G O заказы, G P производство, / поиск.

Информационная архитектура

  • 28 пунктов → 12 (правила разделов Tatiana 01.11.2026): Orders · Today | Delivery · Inbox · Customers | Catalog · Stock | Team · Tasks · Learning | Analytics · Growth · Settings. Production слит в Orders (вид «Make»), новых пунктов в сайдбар не добавляем – новое идёт вкладкой или видом внутри своего раздела.
  • Analytics – 14 подразделов: все 29 нынешних вкладок плюс метрики карточек товара, UTM, блог, маркетплейсы; один период и одно определение выручки.
  • Dashboard / All orders / Overview слились: Today для «что горит», Orders для таблицы, карточка заказа – шторка справа, одна на все экраны.
  • Learning, Buddy, Development, Skill check, Quiz – один раздел Learning с матрицей допусков.
  • Tasks и Active – доска задач; «Active» (лидерборд, цель, бонус) ушёл в Team → Bonus.
  • Growth = Upsell + Marketing + SEO + Content, только владелец.

Dashboard (Overview)

  • Экран Overview (/dashboard, только owner и manager; флорист попадает на Today) – все 20 функций нынешнего дашборда: обзвон пропущенных, 8 KPI, «Needs you now», зоны, недавние заказы, таймер смены, неделя со средним чеком, рейтинги, звонки Ringover, мастер-классы, лента, быстрые действия.
  • Owner видит больше: остановки курьеров на проверку, «View report» / «Full report», закрытие обзвона без звонка. Manager – всплывающее напоминание о звонках с отложением 10 мин × 2.
  • Переехало: пункт меню Overview → переключатель Today | Overview и ⌘K; «Demo requests» и «Courier stops» – строками в «Needs you now»; «Open» у неоплаченного – шторка заказа вместо отдельной страницы.
  • Demo data в шапке – «Quiet day» показывает все пустые состояния, плюс тумблеры Ringover / рейтинги / подписки.

Orders (доска заказов)

  • Orders – рабочая доска, а не таблица. Собрана по реестру функций /orders (233 ID): вкладки дня с «+N not paid», Not ready / To hand over / Delivering / Special / All orders / Archive, каналы, ряд флористок с очередью и «Assign several», все колонки строки, баннеры разбора, NOT PAID с погоней, Call back required, «Примите оплату», лиды сайта, задачи, Closed.
  • Сборка – вид внутри Orders (решение Tatiana 01.11.2026): в полосе вкладок входы Make board · Pre-orders · Peak day · Photo check · Workshops ведут на экраны производства; отдельного пункта Production в сайдбаре не будет.
  • Карточка заказа поверх доски – общая шторка App.openOrder, дополненная блоками реестра (статус, очередь, курьер с советником, фото готового букета, POD, согласование клиента, Quick edit без уведомлений, футер с печатью и Mark complete).
  • Роли видны переключателем стенда: Owner – чипы Refunds / Problem orders, Cancel all unpaid, Clear list, Dismiss all; Manager – окно «Call back required» без закрытия; Florist – баннеры разбора уходят вниз и пусты, Export даёт 403; галочка Trainee – режим только чтения.
  • Взяли у кого: кнопка статуса подписана следующим шагом (как сейчас в CRM, не выпадающий список); «No» в «Hand to courier» справа внизу (safeCancel); автообновление 60 с с паузой при открытой форме – как в коде; /all-orders – отдельный экран-реестр с фильтрами и колонкой Contacted.

Tasks

  • Tasks – одна карточка задачи (шторка) для списка, доски и планёрки: матрица глаголов сведена из TASK-051 / 084 / 096 (Take it on · Done · Approve + Start · Return to work · Reopen · Edit · Back to pool · Cancel / Ask to cancel · Delete), права – по флагам задачи (автор / исполнитель / admin), не по роли.
  • All tasks – три «двери» TasksNav как в CRM (Today · All tasks · People) + четвёртая «Floritta Active» вместо второго пункта сайдбара; тулбар What / View / Whose / Where с счётчиками как в Linear, bulk-панель как в Shopify.
  • Today – колонки по якорям дня (Opening · Midday · Before dispatch · Closing · Any time) с меткой «now», кружок = Done без окна, если фото не нужно; каталог – правая шторка со скелетоном и ошибкой/Retry.
  • Questions – три колонки (группы · список · вопрос), хоткеи ↑↓/Enter, Shift-диапазон, массовые Close / Reassign / Put off с окном подтверждения и плашкой итога.
  • Деньги и баллы – добавлены подтверждения там, где в CRM один клик (Redeem, Fulfil, Reject, Close goal); ошибки лимитов показываются в окне, а не теряются.
  • Стенд: кнопка «Empty state» в шапке каждого экрана переключает пустое состояние; пагинация списка – по 10 на демо (в CRM 30).

Карточка заказа и новый заказ

  • Карточка заказа (s-order-card, /orders/{id}) – в новом дизайне это страница, а не шторка: 162 функции реестра 02 не помещаются в правую панель. Шторка шелла App.openOrder остаётся быстрым просмотром с доски (статусы, оплата, фото, чат, история, меню «…»), а «Edit order» ведёт на эту страницу. Раскладка: баннеры условий (алкоголь, часы лицензии, питомцы, нет способа, переплата) → липкие вкладки Order · Photos · Money · Issues · Delivery · Activity → справа всегда Status & details, Special attention + checklist, Stock.
  • Главное решение по заметкам реестра: каждая панель помечена «With form» (сохраняет «Save changes») или «Saves itself» (сохраняется кликом) – путаница сентября с флагом внимания. Панели с собственным сохранением стоят вне формы, у всех кнопок явный type; Enter в поле не отправляет форму. Деньги разведены по трём подписанным блокам: Payments (форма), Refunds (Stripe, PIN, ИИ-проверка менеджера), Refund request (учёт просьбы).
  • Удаление фото, «×» у ответа клиента, Delete у заметки адреса – всегда видимые кнопки (iPad без ховера). Отказы сервера показаны на экране: ready без фото готового букета, delivered без POD (модалка POD), алкоголь вне часов (модалка), лилии при запрете, 403 для флориста при Save.
  • Условные блоки включаются меню «Demo states» (24 переключателя + «Everything on»); роли: Owner – админские возвраты, Overturn/Uphold, «All problem orders»; Manager – редактирование; Florist – форма только чтение, подмены, фото, флаг и жалоба работают.
  • Форма нового заказа (s-order-create, /orders/create) – полная версия по реестру 03 (86 функций): контексты из Inbox (?conversation_id, draft=1, flora_draft, pay_order, pay_amount) и конструктора – меню «Context & demo»; вариант модалки с доски (скелетон справочников, Cancel с подтверждением, пауза автообновления). Упрощённый s-order-new в 02-orders.html остаётся как быстрый приём по телефону.
  • В шелл стоит перенести: ссылку «Edit order» из шторки App.openOrder на s-order-card; команду палитры «Open order card»; поле корпоративного клиента (corporate/partner) в App.data.customers; событие emit('orders') уже используется.

Inbox и клиенты

  • Inbox – три колонки как в Intercom/Front: слева линии Managers / Support + статус-чипы (Needs action, Waiting, Unresolved, Draft ready, Follow up) и каналы, в центре тред с подписями авторов (manual / Flora · sent by / Flora · auto) и рамкой «Flora's draft» в поле ответа, справа контекст: карточка клиента, связанный заказ, платёжная ссылка Order/Tip, повод, согласия, звонки Ringover, AI.

Форма клиента – отдельный экран с дедупом по телефону/email.
