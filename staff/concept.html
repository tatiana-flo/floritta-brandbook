1. Резюме

Предлагаем перезапустить внутреннее приложение как Floritta Team: пять табов вместо восьми–девяти, экран Today как лента «сейчас / дальше», доска задач в духе Trello и обучение по 3 минуты в смену – всё в утверждённом стиле брендбука (палитра Ivory, квадратные углы, Cormorant Infant + Jost). Цель – убрать «передай второму сотруднику»: каждое поручение становится задачей с исполнителем, сроком, отметкой «увидел» и доказательством, а каждое новое правило – объявлением с кнопкой «Понял» или уроком дня.

Главный вывод аудита: это апгрейд и объединение, а не новая система. В CRM уже есть Task (routine / project / ask; open / in_progress / done / cancelled + approved_at), TaskTemplate с повторами, доска проектов queue / doing / review / done, пул, пуши «New task for you» / «Sent back» / «Thank you»; в обучении – уроки пяти типов, интервальное повторение +1 / +3 / +7 / +30, наставник с чекпоинтами, планы развития, глоссарий, оплачиваемое время. Не хватает: отметки «увидел», объявлений с подтверждением, доски для всех видов задач, эскалации просрочки, мобильных approve / reopen / update, тела урока с фото и видео, сертификатов и push-типа learning. План – шесть фаз (Ф0–Ф5); первые четыре едут OTA без новой нативной сборки.

2. Принципы дизайна

  1. Один вопрос на экран – «что мне делать сейчас?». Today – лента «сейчас / дальше», а не сетка модулей (паттерн Target myDay, Asana My Tasks).
  2. Пять табов: Today · Tasks · Work · Learn · Me. Остальное – стековые экраны или строки в Me.
  3. Брендбук без исключений: Ivory, radius 0 везде; круги только у аватаров, точек статуса и колец прогресса. Акцент #b4595f – только просрочка и тревога, sage #7a8a6b – сделано, warn #b8862e – на проверке.
  4. Типографика: Cormorant Infant 300 – заголовки и большие числа, Jost 300 / 400 / 500 – текст, кнопки Jost 13 px uppercase. Системные шрифты и Ionicons уходят.
  5. Native-ощущение: цели касания ≥ 44 pt, липкая нижняя кнопка действия, bottom-sheets вместо модалок, pull-to-refresh, хаптика при смене статуса и чек-ине.
  6. Стекло (Liquid Glass, iOS 26) только на навигационном слое – таб-бар и appbar; контент матовый; таб-бар сжимается при скролле (Apple HIG).
  7. Уведомления с приоритетом: срочное – отдельный канал; остальное – дайджест в начале смены; тишина вне смены.
  8. Доказательство вместо «на словах»: фото перед упаковкой, фото при закрытии задачи, «Понял» под объявлением.
  9. Без конфетти: недельное кольцо и командная цель смены вместо личного рейтинга (лидерборды демотивируют нижнюю половину).

4. Задачи (Floritta Tasks)

Цель – снять с менеджеров роль ретранслятора. Поручение один раз записывается в задачу; дальше система сама показывает её исполнителю, фиксирует «увидел», напоминает, эскалирует просрочку и приносит менеджеру результат на проверку. Обсуждение – в карточке задачи, не в мессенджере.

Статусы и переходы

Приложение показывает четыре состояния; они однозначно ложатся на существующие поля, миграция статусов не нужна.

В приложении В CRM Кто переводит
To do open создатель / ShiftDistributor / claim из пула
Doing in_progress (started_at) исполнитель – «Start»
Review («на проверке») done, approved_at = null исполнитель – «Send to check»; при proof_type = photo без фото кнопка неактивна
Done done + approved_at менеджер – «Approve & close»; ReviewStrata автоодобряет через 72 ч (есть)
Sent back in_progress + rejection (есть) менеджер – «Send back» с причиной
Cancelled cancelled менеджер; исполнитель – только запрос отмены (есть)

Задачи с requires_review = false (например, «Вернуть вёдра RFH в фургон») закрываются в Done сразу по «Mark as done».

Доска

Одна доска для всех видов задач, не только project: колонки To do / Doing / Review / Done, порядок – board_position (эндпоинт PUT /tasks/board/order уже есть в вебе, выносим в API). Менеджер видит всех с фильтром по человеку (ряд аватаров), сотрудник – своё. Pool – отдельный сегмент (есть scope=pool). Застой 7 / 14 дней подсвечиваем, как в ProjectBoard.

Шаблоны и повторы

Уже есть: TaskTemplate с daily / weekly / monthly, recurrence_days, роль, per_person, время, «зачем это важно», take из приложения, раздача ShiftDistributor в 04:20 и ежечасно. Добавляем только requires_review и экран templates в приложении (список, «Взять» / «Назначить»).

Эскалация просрочки

Предложение (подтвердить у Tatiana): due_at прошёл → через 15 мин push priority исполнителю «Opening checklist is overdue», escalation_level = 1; ещё через 30 мин (+45 от срока) – push менеджеру на смене и строка в Telegram ops-чат, escalation_level = 2, задача попадает в «Нужно внимание». Один проход крона каждые 5 мин поверх существующего tasks:asks-nudge. Для kind = ask оставляем текущие +1 / +3 дня.

Объявления с «Понял»

Менеджер пишет объявление, выбирает аудиторию (роли или люди), включает «нужно подтверждение», опционально привязывает урок. Сотрудник видит объявление первым блоком на Today и в inbox, жмёт «Понял» → announcement_acks. Менеджер на экране объявления видит два списка – подтвердили / ещё нет – и кнопку «Напомнить остальным» (повторный push). Паттерн Blink Mandatory Reads / WorkJam attestation. «Что изменилось» в обучении остаётся: объявление со ссылкой на урок открывает урок после «Понял».

Экран менеджера «Нужно внимание»

Первый блок Today для роли manager / admin: не отметились на смене по графику; просроченные задачи с именами; задачи на проверке (счётчик и список); объявления, которые не подтвердили N человек; заказы без флориста за 30 мин до слота. Ниже – статистика дня (заказы / открытые задачи / просроченные уроки) и быстрые действия: New task, Announce, Who's on. Источник – существующие Tasks / Health и Huddle из веба, собранные в один мобильный ответ GET /api/v1/attention.

Что нужно в API (/api/v1)

Добавить: POST /tasks/{id}/approve, POST /tasks/{id}/reopen, PATCH /tasks/{id} (title, due, assignees, priority), POST /tasks/{id}/seen, PUT /tasks/board/order, GET /tasks?scope=all (менеджер), GET /attention, GET /announcements, POST /announcements, POST /announcements/{id}/ack, GET /announcements/{id}/acks, GET /templates, POST /templates/{id}/assign. Остальное (store, claim, start, done с фото, comments, undone, steps, cancel-request, take) уже есть.

5. Обучение (Floritta Learn)

Что есть

Категории с ролями (AUDIENCE), уроки пяти типов (quiz, photo, link_proof, flashcards, observation), главная мысль своими словами, подпись под декларацией, назначения по ролям с due_days и expires_at, интервальное повторение LearningQuizItem +1 / +3 / +7 / +30, LearningBuddy с чекпоинтами 1 / 3 / 7 / 14 день, планы развития, глоссарий с колодой дня, матрица человек × станция, квартальная аттестация, оплачиваемое время в табеле. Мобильный API покрывает список, урок, submit, acknowledge, глоссарий, план развития.

Что меняем в UX

  • Урок дня после чек-ина: 3 минуты, первым в дайджесте и на Today; это первый LearningAssignment по сроку – данные уже есть, меняется место показа.
  • Кольцо недели вместо месячного: «3 урока + 1 практика», цель корректируется по графику смен (Apple Fitness).
  • Недельный streak с заморозкой: считаем недели, а не дни – смены плавают; одна заморозка в месяц.
  • Review-карточки из существующих LearningQuizItem: экран «Повторить 5 карточек», Знаю / Не знаю, ошибка – завтра (SM-2-подобно, как в бэке).
  • Пути по ролям поверх категорий AUDIENCE: Base & compliance, Handover & client standard, Floristry craft, Delivery – с прогресс-барами; новых таблиц не нужно, путь = категория верхнего уровня + роль.
  • Практика на реальном заказе: урок типа observation создаёт задачу-практику («Собрать 2 спирали на реальных заказах», task 110 в прототипе), наставник подписывает в приложении – это LearningBuddy sign-off и requires_countersign, которых сейчас нет в мобильном API.
  • Сертификаты и допуски из Matrix в приложении: Challenge 25, Fire safety, Pet-safe, станции с датой истечения и кнопкой «Пройти заново».
  • Тело урока: markdown + фото + видео (сейчас HTML превращается в текст и картинки теряются).
  • Push-тип learning: урок дня, срок, повтор, sign-off наставника – сейчас напоминания только в ops-Telegram.
  • Язык EN / RU / UK: переводы уже есть в LearningLessonTranslation, добавляем uk и переключатель на уроке.

Что нужно в бэке

learning_lessons.body_format (text | markdown) и таблица learning_lesson_media (lesson_id, kind photo | video, url, caption, position; видео – ссылка на R2 / YouTube unlisted); генерация PDF сертификата при pass урока с is_certificate = true (DomPDF, в хранилище, ссылка в API); push-тип learning в PushNotifier с четырьмя подтипами; API: GET /learning/review и POST /learning/review/{item} (из LearningQuizItem), GET /learning/certificates, GET /learning/buddy, POST /learning/buddy/{checkpoint}/sign, GET /learning/paths. Глоссарий, квиз-сабмит, план развития – уже в API.

Правило: всё нативное – одним заходом в Ф4. runtimeVersion = fingerprint: любое нативное изменение меняет fingerprint и отрезает OTA от всех предыдущих билдов, поэтому Ф0–Ф3 трогают только JS, а Ф4 собирается один раз и раздаётся через TestFlight / Play.

Риски. (1) Фингерпринт OTA: одно случайное нативное изменение в Ф0–Ф3 отрежет обновления от текущих билдов – проверять npx expo-updates fingerprint в CI.
